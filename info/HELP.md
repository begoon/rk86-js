## Загрузка файлов в эмулятор

Загрузить файл в эмулятор можно через тулбар (выбор файла из встроенного
каталога, drag-and-drop локального файла), через CLI-пакет
[`rk86 --online`](../README.md#терминальный-эмулятор), либо через URL-параметры
адресной строки:

| Параметр | Действие |
|----------|----------|
| `?file=<источник>` или `?run=<источник>` | загрузить и запустить |
| `?load=<источник>` | загрузить без запуска |
| `?handoff=<uuid>` | забрать бинарник из `localStorage` (см. [README](../README.md#автозагрузка-через-url)) |

`<источник>` может быть одним из:

- **Имя из встроенного каталога** — например, `RESCUE.GAM`. Файл берётся из
  встроенного списка эмулятора.
- **Полный URL** — `https://...`, файл скачивается из сети. Имя (а точнее,
  расширение) в конце URL определяет, как файл будет разобран.
- **Data URL** — `data:[;name=<имя>];base64,<payload>`. Без `name=`
  используется `inline.bin`, загрузка с `0000h`. Поддерживается URL-safe base64
  (`-_`).

Примеры:

- <https://rk86.ru/index.html?file=RESCUE.GAM>
- <https://rk86.ru/index.html?file=https://gist.githubusercontent.com/begoon/f4a4e82968d7f581668f218bc17f9ec6/raw/sokoban.bin>

Запуск через `?run=` / `?file=` / `?handoff=` инъектирует `G<addr>Enter`
монитору (а не делает прямой `cpu.jump`), чтобы монитор оставался в чистом
prompt-loop и клавиатурные флаги были согласованы.

### Адрес загрузки и стартовый адрес

Поведение зависит от расширения файла.

- **`.bin` или без расширения** — сырой бинарный файл без заголовка ленты РК.
  Загружается с адреса `0000`.
- **`.bin` с именем, начинающимся на `mon`** (например, `mon32.bin`) — особый
  случай: загружается и запускается с адреса `0x10000 - длина_файла`. Так,
  `mon32.bin` длиной `0800h` (2048 байт) загружается с адреса `F800`.
- **`.GAM` / `.PKI` / `.RK` / `.RKR`** — формат ленты РК с заголовком: байт
  `E6`, начальный адрес (2 байта, big-endian), конечный адрес (2 байта).
  Длина вычисляется из адресов; стартовый адрес = начальный.
- **`.json`** — полный снимок состояния (см. [Снапшоты](#снапшоты) и
  [info/SNAPSHOT.md](SNAPSHOT.md)).
- **Текстовые файлы** — см. [следующий раздел](#текстовые-hex-файлы).

## Текстовые (hex) файлы

Если файл начинается со строки `#!rk86` (байты `23 21 72 6B 38 36`), он
рассматривается как шестнадцатеричный дамп.

```
#!rk86
0000 E6 10 00 20 00 AA BB CC 11 22 33 44 55 66 77 88
0010 11 22 33 44 55 66 77 88
```

Первые 4 символа каждой строки — смещение, чисто информативное. Остальная
часть строки — последовательность hex-кодов (00..FF), количество в строке
произвольное. Все коды собираются в единую последовательность байт.

Строки, начинающиеся с `#`, — комментарии и игнорируются.

После сборки байт файл рассматривается как обычный двоичный (правила
загрузки — выше).

### Теги `!name`, `!start`, `!entry`

В строках-комментариях можно задать специальные теги:

```
#!rk86 !name=file.rk !start=1000 !entry=1005
0000 E6 10 00 20 00 AA BB CC 11 22 33 44 55 66 77 88
0010 11 22 33 44 55 66 77 88
```

Теги можно располагать на разных строках.

- **`!name`** — задаёт имя загружаемого файла (с расширением). Полезно,
  когда хостинг (pastebin, gist под произвольным именем) не позволяет
  контролировать URL: расширение определяет тип файла (`.bin` → сырой,
  `.gam`/`.rk`/`.rkr`/`.pki` → ленточный формат). Если `!name` не задан, имя
  берётся из URL.
- **`!start`** — адрес загрузки для бинарных файлов (`.bin` или без
  расширения). Для ленточного формата РК адрес всегда берётся из заголовка,
  тег игнорируется.
- **`!entry`** — стартовый адрес. Работает и для бинарных, и для ленточных
  файлов.

## Эмуляция магнитной ленты

Эмулятор отслеживает запись в порт `8002` (вывод на ленту в РК). Когда
начинается серия команд записи, эмулятор копит результат; когда серия
заканчивается, выгружает накопленное в виде файла на локальный диск
(`rk86-tape.bin` по умолчанию).

Например, команда монитора `OF800,F8FF` после окончания вывода первых 256
байт сохранит файл с дампом этой области.

## Эмуляция звука

Звук работает через [Web Audio API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API).
Эмулятор ловит обращения к командам `EI`/`DI` и рассчитывает период по тикам
i8080 — частоты получаются точные, не зависят от плавающей скорости
эмулятора.

Демо-видео: <https://www.youtube.com/watch?v=bTCxb3UpqXY>

Проверено на Chrome 88+, Firefox 85+, Safari 14+, Opera 74+.

## Световое перо

Перо эмулируется мышью: позиция курсора задаёт положение пера, левая кнопка
определяет, активно ли перо.

Программный интерфейс:

- Чтение `C001`, бит 4 (маска `10h`) — `1`, если перо активно (нажата
  левая кнопка мыши), `0` иначе.
- Запись `60h` в `C001` — активирует считывание положения. Последующие два
  чтения из `C000` возвращают: горизонталь (0..77), затем вертикаль (0..29).

## Снапшоты

Снапшот — это JSON-файл с полным текущим состоянием эмулятора: процессор,
вся память (64 КБ), клавиатура (включая РУС/ЛАТ, УС, СС), экран (размер,
адрес видеопамяти, позиция курсора).

Поля `start` и `end` информативны и не используются при загрузке. Секция
`memory` состоит из строк по 16 байт; адресное поле задаёт адрес загрузки
строки. Не все адреса должны присутствовать — при ручном составлении
снапшота можно указать только нужные фрагменты.

Кнопка «Snapshot» сохраняет снапшот на локальный диск. Загрузка — через
выбор локального файла, drag-and-drop, либо через URL-параметр `?file=`
(см. [Загрузка файлов](#загрузка-файлов-в-эмулятор)).

Полная спецификация формата — [info/SNAPSHOT.md](SNAPSHOT.md).

### Имитация клавиатурных нажатий

В снапшоте есть секция `boot/keyboard` (в свежесозданном — пустая), куда
можно вписать последовательность клавиатурных событий, выполняющихся сразу
после загрузки.

Пример: ввод `d,fff[enter]` (по 100 мс на нажатие/отпускание), пауза 300 мс,
комбинация `УС+С` (нажать → отпустить):

```jsonc
"keyboard": [
  {
    "keys": [68, 188, 70, 70, 70],   // d , f f f
    "duration": 100,                  // 100мс на каждое нажатие/отпускание
    "action": "press"                 // нажать → пауза → отпустить → пауза → следующая
  },
  {
    "keys": [13],                     // Enter
    "duration": 100,
    "action": "press"
  },
  {
    "keys": 0,                        // для pause keys игнорируется
    "duration": 300,
    "action": "pause"
  },
  {
    "keys": [17, 67],                 // УС, c — нажать обе
    "duration": 20,
    "action": "down"
  },
  {
    "keys": [67, 17],                 // c, УС — отпустить обе
    "duration": 100,
    "action": "up"
  }
]
```

Поле `action`:

- **`down`** — нажать перечисленные клавиши; `duration` — задержка после
  нажатия всех клавиш в группе.
- **`up`** — отпустить перечисленные; `duration` — задержка после отпускания.
- **`press`** — для каждой клавиши последовательно: нажать → задержка →
  отпустить → задержка. `duration` применяется к каждой паузе.
- **`pause`** — задержка `duration` мс; `keys` игнорируется.

Коды клавиш — стандартные PC keycodes (см. <https://keycode.info>). Кнопка
«About / Keyboard» в эмуляторе показывает соответствие клавиш PC ↔ РК.

Количество элементов в `keyboard` неограничено.

## Сохранение памяти эмулятора

Два способа сохранить текущее состояние памяти на локальный диск:

- **Кнопка «Save memory»** — скачивает всю память (64 КБ).
- **Команда `dd`** в [отладочной консоли](#отладочная-консоль) — сохраняет
  произвольный фрагмент: `dd $0 $8000` сохранит первые 32 КБ.

## Visualizer

Visualizer показывает исполняемые команды процессора в реальном времени.
Включается кнопкой `V` в тулбаре (или `Cmd/Ctrl+K, V`). Полностью отключить
визуализатор можно перезагрузкой страницы.

![Visualizer](https://rk86.ru/i/rk86-visualizer.png)

## Полноэкранный режим

Кнопка «Full screen» (или `Cmd/Ctrl+K, F`) переводит эмулятор в полноэкранный
режим через [Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API).
Выход — `ESC`. Эмуляция кнопки РУС/ЛАТ перенесена с `ESC` на `F10`, так как
`ESC` теперь занят выходом из полноэкранного режима.

## Отладочная консоль

Отладчик (`Cmd/Ctrl+K, D`) объединяет экран, дизассемблер и консоль. Полный
список команд консоли (`d`, `dd`, `z`, `w`, `i`, `g`, `s`, `bl`/`be`/`bd`,
`cs`, `t`, `?` и др.) — в [README](../README.md#команды-консоли).

![Console](https://rk86.ru/i/rk86-console.png)

## Взлом игр

Классическая методика поиска переменных в памяти (количество жизней, очки):

1. Запустить игру.
2. Сделать дамп памяти (кнопка «Save memory» или команда `dd` в консоли).
3. Потерять одну жизнь.
4. Сделать новый дамп.
5. Повторять, пока не наберётся серия дампов.

Затем сравнить бинарные дампы программой (не глазами!) на предмет ячейки,
которая монотонно убывает или возрастает. Поставить брекпоинты на адекватных
кандидатов (`be 1 type:write address:$XXXX`) и найти место, где значение
меняется. Готово — патчи и читы накладываются по этому адресу.

Для побайтового сравнения файлов подойдёт, например,
[`cmp.py`](https://github.com/begoon/rk86-js/blob/master/cmp.py).

## Локальная разработка для РК

Простой цикл разработки: исходник на ассемблере → сборка локально →
коммит в публичный репозиторий → запуск через `?file=<raw URL>`. Альтернатива
без коммита — `bunx rk86 --online prog.bin`
([README](../README.md#терминальный-эмулятор)).

Пример проекта — [rk86-example](https://github.com/begoon/rk86-example):

```asm
        org 0

        lxi  h, msg
        call 0f818h          ; печать строки через монитор
        jmp  0f86ch          ; возврат в монитор

msg:    db   'EXAMPLE', 0dh, 0ah, 0
```

Makefile:

```make
TARGET = rk86_example
RUN    = https://rk86.ru/index.html?file=

all: build hex

build:
	zasm --asm8080 -l0 $(TARGET).asm

hex:
	python rk86_hex.py -i $(TARGET).rom -o $(TARGET).bin

run:
	open $(RUN)https://raw.githubusercontent.com/begoon/rk86-example/main/$(TARGET).bin

clean:
	-rm $(TARGET).rom
```

Цикл:

1. Редактируете `rk86_example.asm`.
2. `make build` → `rk86_example.bin`.
3. Коммит + push, чтобы файл был доступен по `raw.githubusercontent.com/...`.
4. `make run` открывает эмулятор с этим файлом.

Альтернативно, без публичного репозитория, использовать
[ассемблер прямо в браузере](https://rk86.ru/asm/) (кнопка «Ассемблер» в
тулбаре или `Cmd/Ctrl+K, A`) — он сам соберёт `.rk` и передаст эмулятору.
